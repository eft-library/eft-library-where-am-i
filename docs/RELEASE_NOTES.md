# 클라이언트 Release 준비 — 2026-10-19

이번 배포의 제품 버전은 4.0.0이며 앱·파일 버전은 4.0.0.0으로 표시한다. 이후 수정 배포는 4.0.1, 기능 추가 배포는 4.1.0처럼 관리할 수 있다. 배포 횟수와 버전 숫자가 반드시 일치해야 하는 것은 아니다.

## 화면 변경

창 바깥 여백과 제목 표시줄을 어두운 테마로 맞췄다. 폴더 선택 버튼은 “스크린샷 폴더 선택”으로 변경했고 버전 정보는 상단 오른쪽 “앱 버전” 버튼으로 별도 창에서 확인한다. Windows 버전에 따라 제목 표시줄 색상 지원에 차이가 있을 수 있다.

스크린샷과 로그의 경로·수집 상태를 각 카드의 “스크린샷 경로 보기”·“로그 경로 보기”로 분리했다.

폴더 선택 버튼은 각각의 카드 상단에 배치하고 버튼 텍스트의 좌우 여백을 적용했다. 직접 지정 경로 안내 문구는 화면에서 제거했으며, application 로그가 없는 상태는 “로그 감지 대기”로 표시한다. 자동 탐색·저장 경로 정책은 유지한다.

버튼은 주요 동작(주황), 폴더 선택(파랑), 보조 동작(회색), 종료(붉은 테두리)로 구분한다. 마우스·키보드 선택 상태를 강조한다.

감지 시작·중지 기능을 제거하고 사용자 확인 후 항상 감지하도록 변경했다. 기존 중지 설정은 무시한다. 현재 맵 열기·프로그램 종료는 로고 오른쪽으로 옮겨 하단 버튼 영역을 제거했다.

최근 활동은 표시·보관 건수를 구분하고 오류 필터의 빈 상태를 안내한다. 최대 100개 목록은 가상화를 끄고 픽셀 스크롤을 사용해 중첩 스크롤과 새 항목 삽입 시 표시를 보완했다. 활동 필터는 WPF 기본 CollectionView 대신 별도 표시 목록으로 관리하며, 갱신 시 목록 전체를 지우거나 교체하지 않는다. 실제 Windows에서 발생한 일시적인 목록 사라짐의 원인은 아직 확정하지 않았으므로 같은 환경에서 재확인이 필요하다.

## 반영한 기능

- 스크린샷 파일명 좌표 전송, 최신 대기값 유지·제한적 재시도·취소.
- application/output 로그 증분 읽기와 맵·레이드 시작·GameTimer 기준 연결.
- 지정 Logs 범위 우선, 실행 폴더 시각에 따른 신규 실행 전환과 이전 상태 초기화.
- 감지/전송 상태·현재 맵 브라우저 링크·최근 활동 100개·오류 필터·창 크기 대응.
- 사용자 지정 경로 마스킹 수집 및 완료 상태 보관.
- 버전 확인·공식 다운로드 페이지 안내와 맵 별칭 조회·정상 캐시 대체.

## 연동 상태와 범위

타이머의 백엔드 수신·웹 BTR 자동 적용, 버전·별칭 API 구현은 별도다. 해당 API가 없는 서버에서는 조회 실패와 캐시/내장 대체가 예상 동작이다. API 성공 응답은 웹 반영 완료를 뜻하지 않는다.

좌표는 게임 스크린샷 방식을 사용한다. 정확한 종료 감지·실제 트랜짓 연결·로그 좌표·BTR 정차 이벤트 수집은 포함하지 않는다. 앱 내 지도·수동 맵 선택은 추가하지 않으며, 앱 내 실시간 타이머·이력 영구 저장/내보내기·독립 설정 페이지·자동 설치도 추가하지 않는다.

## 검증

자동 검사는 가짜 HTTP와 임시 파일·정제 샘플을 사용한다. 패키징 스크립트는 C# 검사·Python 테스트 후 Release Windows x64 self-contained 단일 실행 파일을 publish하고 ZIP·SHA-256·manifest를 만든다. ReadyToRun과 trimming은 사용하지 않는다.

실제 Windows 실행·DPI·게임 플레이·서버/웹 통합은 [검증표](WINDOWS_VALIDATION.md)를 따른다. 이 문서는 공개 배포·코드 서명·이번 빌드의 백신 검사 완료를 뜻하지 않는다.
